
# FT-006: CLI Client

## Problem

У Feedium есть gRPC/HTTP API (`api/feedium/`: `health`, `source`, `post`, `summary`), но нет типизированного программного клиента. Любая ops- или debug-операция сегодня требует `grpcurl`/`curl` с ручной сборкой payload либо одноразового кода на Go.

Последствия:

- Проверка состояния системы и просмотр её содержимого (источники, посты, саммари) медленны и подвержены ошибкам: payload собирается руками при каждом обращении.
- Batch-автоматизация поверх MVP API затруднена — нет стабильной точки входа, которую можно вызвать из скрипта и распарсить вывод.
- Отладка серверной части требует переключения на сторонние инструменты вместо одного предсказуемого CLI, говорящего на тех же контрактах, что и сервер.

## Task

Обеспечить единый read-only CLI-инструмент, дающий доступ ко всем четырём MVP-сервисам Feedium без написания кода и ручной сборки gRPC-запросов.

1. CLI выполняет проверку здоровья сервиса (`health`).
2. CLI даёт операции чтения — просмотр списка (list) и получение по идентификатору (get) — для источников (`source`), постов (`post`) и саммари (`summary`).
3. Вывод пригоден и для человека, и для машинной обработки: при выборе машиночитаемого формата результат — валидный структурированный вывод, который можно распарсить в скрипте.
4. При недоступном или ответившем ошибкой сервере CLI завершается с ненулевым exit code и пишет внятное сообщение в stderr; при успехе — exit code 0.

Конкретный фреймворк CLI, набор флагов, точные форматы вывода, способ резолва endpoint и устройство соединения с сервером — задача Design-фазы.

## Out of Scope

- Любые мутации: создание/изменение/удаление источников и постов, запуск суммаризации. CLI на этом этапе только читает.
- Аутентификация и авторизация сверх той, что уже предоставляет API.

## Users

- **Разработчик / оператор Feedium** — проверяет состояние и содержимое системы и автоматизирует проверки поверх API, не написав ни строки клиентского кода и не собирая gRPC-запросы вручную.

## Context

- Разрабатывается MVP Feedium; FT-001..FT-005, FT-007..FT-009 обеспечивают каркас, хранилище, управление источниками и постами, суммаризацию, масштабируемую обработку событий и автоматический сбор контента. Все четыре сервиса (`health`, `source`, `post`, `summary`) уже существуют в `api/feedium/`.
- Исходная попытка FT-006 ограничивалась сервисами `health` и `source` (post/summary выносились в «FT-007+»). На данный момент FT-005/007/009 завершены, и API для `post` и `summary` доступен — поэтому переписанный CLI покрывает все четыре сервиса сразу.
- CLI должен обращаться только к публичным gRPC-контрактам из `api/feedium/`; внутренние слои сервера — вне его доступа.

## Acceptance

- При работающем сервере команда проверки здоровья завершается с exit code 0 и печатает ответ; команды list и get по каждому из сервисов `source`, `post`, `summary` возвращают корректные данные.
- При недоступном сервере любая команда завершается с ненулевым exit code и сообщением об ошибке в stderr.
- При выборе машиночитаемого формата вывод — валидный структурированный результат, пригодный для разбора в скрипте.
- Поведение покрыто тестами.
